# SMEWSYS — Stitch → Figma → Development Handoff Checklist

## Stitch generation
- [ ] Master prompt applied.
- [ ] Wireframe supplied as visual reference.
- [ ] `design.md` rules followed.
- [ ] Home page established as the visual baseline.
- [ ] Desktop and mobile states generated.
- [ ] No unauthorized page types introduced.

## Design consistency
- [ ] Same header.
- [ ] Same footer.
- [ ] Same button variants.
- [ ] Same card system.
- [ ] Same typography scale.
- [ ] Same spacing rhythm.
- [ ] Same radius and border treatment.
- [ ] Same teal accent behavior.

## UX
- [ ] Every page has a clear purpose.
- [ ] Primary CTA is obvious.
- [ ] Navigation matches sitemap.
- [ ] Breadcrumbs appear where useful.
- [ ] Portfolio filters are understandable.
- [ ] Contact form has validation states.
- [ ] Legal/system pages have recovery paths.

## Responsive
- [ ] Large desktop
- [ ] Desktop
- [ ] Tablet
- [ ] Mobile
- [ ] Small mobile
- [ ] No overflow
- [ ] Touch targets >=44px

## Accessibility
- [ ] Contrast checked
- [ ] Keyboard navigation
- [ ] Focus states
- [ ] Semantic headings
- [ ] Form labels
- [ ] Error messaging
- [ ] Alt text
- [ ] Reduced motion

## Figma
- [ ] Paste/export approved Stitch screens.
- [ ] Convert recurring UI into components.
- [ ] Create variables/tokens from `design-tokens.json`.
- [ ] Create desktop/tablet/mobile variants.
- [ ] Document component states.
- [ ] Add developer annotations.

## Development
- [ ] Reuse design tokens.
- [ ] Build shared header/footer.
- [ ] Build reusable service/project/card components.
- [ ] Build service-detail and case-study templates.
- [ ] Implement accessible forms.
- [ ] Validate against approved Figma screens.
